# 乌托帮 UTOBANG · 产品稿 v0.6

> 一句话定位:先帮后托的开店服务台。「帮」是 AI 把账算明白,「托」是真人把活儿接过去。

## 1. 目标用户与核心问题

小微创业者(首次或二次开店),分两条主线:

- **线下实体店**:选址、装修、证照、排班是主战场。最怕的是"签了约才发现算不过账"。
- **线上店铺**:流量、转化、投流、退货率是主战场。最怕的是"钱投出去了单没回来"。

共同痛点:开店前没人帮着把账算清楚;开店后数据散落各处,不知道该盯哪个数字、该做哪件事。

## 2. 产品叙事:帮 → 托

用户旅程与商业模式同构,菜单即愿景:

| 阶段 | 用户在做什么 | 乌托帮给什么 | 对应菜单组 |
|---|---|---|---|
| 想开店 | 犹豫、比较、怕亏 | 三步向导 + AI 生成开店清单与预算 | 开店帮 |
| 筹备中 | 跑证照、谈租约、备货 | 清单打勾推进、预算联动、风险实时预警 | 开店帮 |
| 开业后 | 天天看流水、救火 | 运营看板、数据报表、AI 诊断、营销方案 | 运营托 |
| 忙不过来 | 想找人代管 | 真人顾问 1v1、代运营对接 | 运营托 · 托管服务 |

## 3. 信息架构

三大板块:**帮(开店帮助)/ 托(运营托管)/ 自定义**。
当前项目入口装配「帮 + 自定义(模型设置)」;「托」、账号与订阅属于可选扩展能力。

```
业务前台(商户视角)                     管理后台(扩展服务,平台视角,演示数据)
├─ 帮 · 开店帮助                        ├─ 平台看板(MRR/增长漏斗/方案分布)
│   ├─ 开店设置(未建店时,三步向导)      ├─ 用户与订阅(商户列表/搜索)
│   ├─ 总览                            └─ AI 用量监控(调用量/成功率/成本)
│   ├─ 开店清单        [AI]
│   ├─ 预算测算
│   ├─ 选址分析|平台选择 [AI]
│   ├─ 风险识别        [AI]
│   └─ AI 参谋         [AI]
├─ 托 · 运营托管(扩展能力)
│   ├─ 日常运营        [AI] 🔒开业后解锁
│   ├─ 数据报表             🔒开业后解锁
│   ├─ 营销活动        [AI] 🔒开业后解锁
│   └─ 托管服务             (永不上锁,兼转化页)
└─ 自定义
    ├─ 订阅与账单(扩展能力)
    └─ 模型设置(当前项目)
```

状态机:`未建店 →(三步向导)→ 筹备中 →(清单≥60% + 标记开业)→ 营业中`。
每个开店项目选择一条主线（线下青 #14606E / 线上黛紫 #5A4FA2），并独立持有店铺信息、清单、预算参数、风险、候选列表和参谋对话历史；顶部项目选择器负责在多家店之间切换。
**线上/线下主线的切换与配色只作用于「帮」板块** —— 托、自定义板块的内容不随主线变化,不显示切换控件。

## 4. 页面规格(要点)

### 4.1 开店设置(向导,未建店时的首屏)
- 步骤 1 选主线:线下/线上两张大卡,写明各自主战场与能力点
- 步骤 2 店铺信息:店名、品类、**核心商品/服务**(AI 理解生意的关键输入)、客单价、预算上限;线下补城市/面积/商圈,线上补货源/平台/内容能力
- 步骤 3 AI 生成:产出 5 阶段开店清单(每项含预估金额),客单价等参数同步预填预算引擎;AI 失败自动落内置模板(金额按参数实时计算),流程永不中断

### 4.2 开店清单(核心页)
- 按阶段分组,逐项打勾;带金额任务合计 = 开店账
- 进度条 + 三态统计;完成 ≥60% 解锁「标记已开业」
- 「AI 重新定制」按钮(消耗额度)

### 4.3 预算测算
- 双计算引擎:线下(房租/装修/设备/客流模型)、线上(投流/转化/佣金/退货模型)
- 线下经营假设支持两种收入方式：客单价 × 日均付费客流；或每时段价格 × 可售时段 × 场地/资源数 × 利用率。预约制支持 30/60 分钟等自定义时长，并输出折合时薪、月预约量和保本利用率
- 签名元素**保本刻度尺**:当前预估 vs 保本线,缺口/富余实时标注
- 12 个月现金流(含爬坡系数 RAMP),回本周期、现金流转正月
- AI 预算体检(深度帮起):逐项比对同品类行情,给存疑项与建议

### 4.4 风险识别(双层)
- **规则引擎**(免费):实时联动当前项目的品类、核心业务、预算参数和选址 / 平台报告。线下盯房租占比/备用金/回本周期/沉没成本/人力占比与候选点评分;线上盯投流占比/ROI/退货率/转化率/备货覆盖与平台匹配。行业规则按项目类型生效，非餐饮项目不能套用食品证照风险。高18/中9/低4 扣分制健康分 + 五维雷达(现金流/市场/运营/供给/合规)
- **AI 深度扫描**(深度帮起):补规则盲区(租约条款、平台政策、季节性),输出监测指标清单

### 4.5 选址分析 / 平台选择
- 页面默认值来自当前项目：城市、品类、核心业务及预算中的面积、租金、定价 / 预约模型；切换项目后自动切换
- 线下:六维评分(需求/客群/竞争/租金/交通/合规)+ 谈判要点，选定候选后可把实际面积和租金同步回预算;线上:平台匹配度 + 主攻/辅攻 + 冷启动路径
- 候选列表可对比,数量随订阅档位(1/5/10)

### 4.6 AI 参谋(双人设)
- 线下参谋(零售 15 年)/ 线上参谋(千万 GMV 操盘手),对话历史按开店项目隔离
- 系统提示词注入当前项目的收入模型与实时经营数字(启动资金/保本线/净利/回本),回答必须用数字
- 工具箱:4 个一键任务(谈租话术/筹备清单/活动设计/差评模板 等)

### 4.7 日常运营 / 数据报表(开业后)
- 运营页管"做":本周待办、AI 运营诊断(30 天数据喂给模型,产出问题→原因→动作)、策略卡
- 报表页管"看":线下=每日营业额 vs 保本线、时段客流分布、坪效;线上=转化漏斗(曝光→进店→下单→成交)、渠道结构、每日 GMV vs 保本线

### 4.8 营销活动(开业后)
- 输入:目标(开业引爆/日常拉新/复购唤醒/清库存)+ 预算 + 时长
- 输出:3 个玩法(含金额)、四渠道预算分配、预期单量、风险提醒;AI 失败落模板

### 4.9 托管服务(「托」的落点,永不上锁)
- 服务矩阵:真人顾问 1v1(月 2 次)/ 代运营对接(内容/投流/客服,按效果结算)/ 月度经营复盘
- 认证顾问卡片(预约)、代运营需求单(提交)
- 非全托管用户点击 → 付费墙引导,页面兼作转化橱窗

### 4.10 订阅与账单

|---|---|---|---|
| AI 次数 | 3 次/月 | 100 次/月 | 不限 |
| 候选方案 | 1 | 5 | 10 |

### 4.11 管理后台(演示数据)

## 5. AI 能力矩阵与契约

所有能力统一走 `POST /api/ai/complete`,前端负责组 prompt、后端负责调模型。结构化输出遵循统一契约:**系统提示词声明"只输出 JSON + 字段定义(含字数上限)"**,前端 `parseJSON` 剥离代码块标记后解析,失败展示兜底 UI 或内置模板。

| 能力 | 页面 | 输出契约(JSON 字段) | 档位 |
|---|---|---|---|
| 开店清单生成 | 向导/清单 | groups[5]{name,items[]{t,cost,note}}, tips[2] | 免费 |
| 选址/平台评估 | 选址 | score, verdict, dimensions[6], strengths, risks, actions, costHint | 免费 |
| 预算体检 | 预算 | verdict, score, issues[3]{item,level,comment}, suggestions[3], cashTip | 深度帮 |
| 深度风险扫描 | 风险 | summary, extra[]{title,level,why,fix}, watchlist[3] | 深度帮 |
| 运营诊断 | 运营 | summary, highlights[2], problems[3]{title,why,fix}, todos[3] | 免费 |
| 营销方案 | 营销 | title, hook, plays[3]{n,detail}, channels[4], kpi[2], warn | 免费 |
| 参谋对话 | 参谋 | 自由文本(250 字内,注入经营数字) | 免费 |

计费口径:以上任一次调用 = 1 次 AI 额度。

## 6. 技术架构:一套代码,按能力装配

### 6.1 运行模式

| | 本机运行模式 | 云端扩展服务 |
|---|---|---|
| 定位 | 开发者/懂技术的老板自己搭,接自己的 Key | 注册即用,不用配任何东西 |
| 板块 | 帮 + 自定义(模型设置 / 数据存储) | 帮 + 托 + 自定义(订阅账单) |
| 后端 | **Python(FastAPI)** | Node(Express) |
| 模型 Key | 用户自己的,存本机 | 平台的,用户看不到 |
| 账号 | 无 | JWT 注册登录 |
| 数据 | SQLite 默认落库，可配置 MySQL | SQLite 落库,跨设备 |
| AI 次数 | 不限 | 按档位计量,服务端拦截 |
| 订阅 / 付费墙 / 平台后台 / 真人托管 | 无 | 有 |
| 模型设置页 | 有 | 无(平台 Key 不能暴露) |

### 6.2 代码分布

```
当前仓库 utobond-open/
  packages/core   预算引擎、风险规则、内置模板、AI 能力契约(纯 JS,带单测)
  packages/ui     业务界面(React),按 edition 装配 —— 两版共用,不分叉
  apps/server     Python/FastAPI:多 Provider AI 网关 + 模型设置(带 pytest 单测)

可选云端服务仓/
  packages/ai     Node 版多 Provider 网关 + Express 路由(带单测,供云端后端用)
  apps/server     账号 / 订阅 / 计费 / 平台后台
```

core 与 ui 由当前仓库维护,其他服务可以通过 `file:` / submodule / registry 引用。
**业务页面不分叉** —— 差异全部收敛到 `editions.js` 的几个布尔开关上
(`ops` 关掉整个「托」板块,`settings` 打开模型设置,`billing/metering/admin` 是云端商业层)。
多 Provider 适配逻辑有 Python、Node 两个实现,行为契约一致,各自有等价单测钉住。

### 6.3 AI 网关

```
浏览器 ──POST /api/ai/complete { messages, system, capability }──▶ 服务端
                                                                     │
        本机模式:直接转发,配置来自用户 ◀──────────────────────────┤
        云端服务:鉴权 → 档位/额度门禁 → 转发 → 用量落库 ◀──────────┘
                                                                     ▼
                              OpenAI 协议 / Anthropic 协议 → 任意供应商
```

云端服务可用三个注入钩子挂接业务逻辑:`resolveConfig`(用谁的配置)、
`guard`(放不放行)、`onUsage`(记不记账)。

选型理由:
1. **网关模式**:Key 不出服务端;换供应商 = 换一行配置,不用改代码
2. **只认两种协议**:`openai` 与 `anthropic`。中转站、DeepSeek、Kimi、智谱、通义、Ollama 全是前者,一套适配吃下
3. **零 SDK 依赖**:Python 侧只用 httpx、Node 侧只用原生 `fetch`,用户不用为换供应商装第二个包,中转站的各种小差异也好绕(比如 `max_tokens` / `max_completion_tokens` 自动重试)
4. **前端零 AI 依赖**:web 只知道 `/api/ai/*`,可独立部署到任意静态托管
5. **capability 贯穿全链路**:前端每次调用带能力 id,云端据此判档位、扣额度、归因成本

## 7. 非功能与约束

- AI 全链路必须有降级:超时/503/解析失败 → 内置模板或兜底文案,流程不中断
- 提示词内所有金额、比率来自实时计算引擎,禁止模型自行虚构用户数据
- 演示数据(管理后台、经营模拟曲线)必须带「演示数据」标识
